Why this topic works

00 / INTRODUCTION

A parking system is small enough to design end-to-end in one assignment, yet it touches every SDLC phase in a visible way: real users, real state changes (empty → reserved → occupied), and a real transaction (the parking fee). That makes it easy to justify each phase with a concrete example rather than an abstract one.

The five phases

01–05 / SDLC
LEVEL 1

Requirements Analysis

Establishes exactly what the system must do and how well it must do it, before any design work starts.

Functional
  • User registration and login
  • View available parking slots
  • Reserve a parking slot
  • Record vehicle entry and exit
  • Calculate parking charges
  • Make and record payments
  • Admin manages users, slots and bookings
Non-functional
  • Security
  • Reliability
  • Fast response
  • Easy-to-use interface
  • Data accuracy
LEVEL 2

System Design

Translates requirements into structure — how data, screens, and logic fit together before code is written.
